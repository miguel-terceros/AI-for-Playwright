
Built-in Agents and MCP tools:
    - different agents == different list of MCP tools
    - list of actions is very limited

Playwright MCP:
    - standart set of tools
    - rich(er) tool list
    - snapshots keep accumulating in the context window
    - caching mechanisms!
    - 2025: more tokens used; 2026: now cheaper
    
Common Playwright MCP demos:
    - "open the app {url}, explore the ENTIRE app, produce test cases in plain English"

Playwright Agents:
    - Planner: explore app, produce a test suite (file)
    - Generator: take the test suite, convert to scripts
    - Healer: fix failing test scripts

    - Takeaways:
        - default planner agent produces superficial work - yes
        - use my prompt? - no!
        - planner agent == starter template (at best)
            - improve it 
            - add domain-specific context

- Healer agent:
    - generic agent usually does the job well too

    - risks!
        - treat the symptom vs. root cause
        - fixing a locator is OK
        - adding waits
        - (wrong) purpose - "make the test pass" (vs. verify correct functionality)

    - alternative flows:
        - create and use a Requirements Analyst agent
        - use agents to produce questions
        - explore and create test yourself, ask 'planner' to find gaps in YOUR work

    - AI cannot be held responsible

MCP vs. CLI 
    - MCP: snapshot saved to disk AND injected into context window
    - CLI: snapshot saved to disk, MAY be read by agent

    - MCP == entire snapshot all the time
    - CLI == part of snapshot SOMETIMES

MCP vs CLI experiment:
    - same agent
    - same model
    - same thinking effort
    - same code base
    - same Takeaways

    - short vs. long-running tasks
